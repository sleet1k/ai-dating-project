2. СТАБИЛЬНЫЙ ФУНКЦИОНАЛ (РЕАЛИЗОВАННЫЕ МИЛЬСТОУНЫ)
⚙️ Инфраструктура и Логика очередей
Изоляция сессий: Для первоначального парсинга данных профиля юзера создается быстрая, изолированная короткая сессия Telethon. Она выполняется строго до запуска основного слушателя анкет. Это полностью решило проблему рассинхрона, когда команды /myprofile или Профиль попадали в общую очередь и вызывали спам командами отмены в чат бота.
Асинхронный Queue Worker: Реализована последовательная обработка через asyncio.Queue. Скрипт корректно обрабатывает альбомы (Media Groups), отсекает дубликаты по grouped_id, скачивает только первое фото анкеты и игнорирует системные сообщения.
Мягкое прерывание: Внедрен перехват ввода символа 0 + Enter во время работы воркера. Это позволяет аккуратно остановить прослушку и вернуться в главное меню CLI без аварийного завершения через Ctrl+C.
🤖 Логика Движков (Engines)
Абстракция: Все боты унаследованы от BotEngine. Скрипт динамически переключает обработчики контента.
Бинарные боты (Дайвинчик, Blurrr): Настроена точная обработка эмодзи-кнопок. Для Blurrr исправлен рассинхрон кнопок: 🗑️ — строгий дизлайк, 🔥/💗 — лайк.
Рейтинговые боты (Бибинто): Реализован режим mode="score". Промпт переключается на генерацию оценки от 1 до 10. Нажатие на кнопки заменено прямой отправкой текстовых сообщений с цифрой оценки (1-10) и командой назад для пропуска, что гарантирует 100% стабильность работы.
Умная ротация при лимитах: Если текущий бот присылает сообщение об исчерпании лимитов («На сегодня хватит анкет»), воркер пишет статус в консоль, ставит паузу 5 секунд и автоматически переключает сессию на следующий сервис по цепочке: Дайвинчик ➔ Бибинто ➔ Blurrr.
📝 Интерфейс и Отладка
Интеграция настроек: Мастер первой настройки (Setup Wizard) при отсутствии .env запрашивает API_ID, API_HASH и кастомный DOWNLOAD_PATH, генерируя конфиг на лету.
Геймификация CLI: Подключен модуль phrases.json. Во время ожидания ответа VLM и отправки реакций скрипт выводит случайные «живые» фразы разработчика («Сканирую вайб анкеты...», «Ну и описание...», «Ёбаный рот, это нам надо!»).
Глубокое логирование: Функция write_history_log пишет данные по абсолютному пути в data/history.md. Лог содержит: имя бота, вердикт, причину отказа от ИИ, сырой текст из Telegram и ответ терминала.
СЛЕДУЮЩЕЕ ПОКОЛЕНИЕ (БЭКЛОГ И СПЕЦИФИКАЦИИ ДЛЯ RAG)
Каждый блок ниже представляет собой целевую задачу. Информация структурирована так, чтобы RAG-модель могла считывать требования без двусмысленности.
Мильстоун 1: Оптимизация Промптов и Токенизация (Приоритет: Высокий)
Проблема: Кириллица неэффективно бьется на токены. Одно русское слово занимает до 4-6 токенов. При удаленной работе с ноутбука base64-строки фото забивают дефолтный контекст LM Studio (1024 токена), вызывая Error 400.
Спецификация решения:
Локальный Токенизатор: Интегрировать легковесный transformers.AutoTokenizer от Qwen на стороне клиента. Скрипт должен замерять объем токенов до отправки запроса по локальной сети.
Адаптивное сжатие: Если токенизатор видит превышение лимита, модуль vlm_analyzer.py через Pillow динамически сжимает разрешение изображения (например, до 512x512) и снижает качество JPEG до 75%, пока пакет не уложится в рамки целевого окна (например, 4096 токенов).
Англоязычные Промпт-Теги: Переписать внутренний системный промпт VLM на жестко структурированный английский язык (English Prompt-Tagging). Вместо длинных описаний использовать синтаксис правил и ключевых слов. Это снизит вес промпта в токенах в 2-3 раза и повысит точность логики локальной 8B модели.
CLI-Управление: Вынести тонкую настройку критериев промпта (фильтры по именам, возрастам, стоп-словам) прямо в CLI-меню настроек, убрав хардкод из файлов скрипта.
Мильстоун 2: Анализ Мультимедиа и Видео-кружков (R&D)
Проблема: Фейковые анкеты используют обработанные фото, но записывают реальные видео-кружки (video_note). Необходимо научить модель анализировать динамику на видео.
Спецификация решения:
Перехват медиа: В tg_client.py добавить триггеры на типы данных event.message.video и event.message.video_note.
Нарезка кадров (Keyframe Extraction): Использовать высокоскоростные библиотеки decord или pyav. Скрипт должен выдергивать из видеопотока 3-5 равномерно распределенных ключевых кадров прямо в оперативную память (без лишних дисковых операций записи/чтения).
Массив картинок (Multi-Image Prompting): Сформировать из полученных кадров массив объектов image_url и отправить их в VLM единым пакетом. Промпт должен быть модифицирован: "Перед тобой последовательные кадры видео-анкеты. Оцени мимику, адекватность и соответствие критериям внешности".
Мильстоун 3: Гибридная Архитектура, Облако и Мобильный Деплой
Спецификация решения:
Выбор API/Local при старте: Расширить Setup Wizard. Добавить переключатель: 1. Локальный сервер (LM Studio) или 2. Облачный API.
Интеграция Облачных провайдеров: Добавить коннекторы для внешних API (Gemini API / Flash / Pro). Использование Gemini Flash решит проблему нехватки локальной VRAM на мобильных устройствах/ноутбуках, предоставляя бесплатное/дешевое контекстное окно в 1 миллион токенов, идеально переваривающее тяжелые видеофайлы.
Docker & Термукс: Оптимизировать скрипт для работы в изолированном Docker-контейнере и консольной среде Termux на Android. Убрать любые GUI-зависимости, оставив чистый асинхронный CLI.
Автоматизация LM Studio: Для локального режима добавить Windows PowerShell / Bash скрипт, автоматизирующий запуск процесса LM Studio и фоновую фолдер-загрузку весов модели при старте дейтинг-агента.
Мильстоун 4: Модернизация Интерфейса (CLI HUD & Web UI)
Спецификация решения:
CLI HUD: Переработать вывод терминала в боевом режиме. Скрыть бесконечный лог бегущих сообщений. Сделать фиксированную шапку (HUD) вверху экрана:
Uptime: [время] | Обработано анкет: [X] | Лайков: [Y] | Дизлайков: [Z]
Строка истории последних 10 действий в формате символьного трекера: [ ----+--++- ] (где - — дизлайк, + — лайк).
Локальный Web UI: В качестве финального этапа разработать минималистичный локальный веб-интерфейс управления (Cyberpunk Black стиль) на базе FastAPI/Streamlit для мониторинга анкет, изменения промптов на лету и просмотра графиков аналитики матчей.
ИНСТРУКЦИЯ ДЛЯ ИИ-АГЕНТА (RAG INGESTION VECTOR)
⚠️ ПРАВИЛО КРИЗИС-МЕНЕДЖМЕНТА ДЛЯ ИИ:
При получении задач на модификацию кода данного проекта, ИИ-ассистент обязан следовать паттерну точечного редактирования. Массовый рефакторинг рабочих файлов проекта, массовое переписывание комментариев или изменение не связанных с задачей функций СТРОГО ЗАПРЕЩЕНЫ. Каждое изменение вносится изолированно, шаг за шагом, сохраняя работоспособность асинхронной очереди asyncio.Queue и модульных движков в engines/.
Раз в 3 итерации кода агент должен напоминать пользователю о необходимости закоммитить изменения в Git.
